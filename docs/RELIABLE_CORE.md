# Надёжное учебное ядро

Этап выполняется поверх существующего приложения. Checkpoint перед изменениями: f17e653. До миграций создан custom-format pg_dump, проверенный через pg_restore --list. Расположение копии сообщается владельцу отдельно; секреты и дампы не коммитятся.

## Схема и установка

Сохранены исходные две миграции. Четыре следующие миграции восстанавливают недостающие enum и поле provenance, добавляют основание подтверждения результата, lifecycle объявлений и достоверность назначения варианта. Они применимы как к исходной базе со schema drift, так и с нуля. accepted_requires_evidence защищает обязательные поля на уровне PostgreSQL; связь доказательства с конкретным результатом дополнительно проверяет доменный сервис.

`prisma migrate deploy` выполняет только структурные миграции. `prisma:seed` — create-only bootstrap дисциплин и шести упражнений САПР. Он не создаёт dev-аккаунты и не меняет существующие записи. Для действующей базы одноразовая сверка данных выполняется `npm run db:repair-academic`, с полным before/after в AuditLog.

## Данные

Неподтверждённые сроки ОТУ, СОВД и VR отменены, а не заменены другой догадкой. ЛР4 ОТУ остаётся черновиком. Ошибочная ссылка СОВД на пособие ОТУ заменена официальным заданием по СОВД; это не подтверждает дедлайн. Назначения преподавателей без источника помечены как кандидаты, фамилии сохранены. Seed-варианты без доказательства сохранены как UNVERIFIED и не показываются персональными.

Неподтверждённые объявления о вариантах СОВД и реплике о ЛР4 сохранены как черновики; подтверждённое расписание САПР связано с документом. Журнал фильтруется по явно записанной области группы, а не по членству автора. Точные старые E2E-задачи и объявления архивированы; связанные сроки отменены. Ни одна строка не удалена. Прогресс, XP и достижения владельца не сбрасываются.

Подтверждённые сроки САПР из раздела «Дедлайны для приема/сдачи расчетного задания» ведомости «осень 2026»: Моп 22.09, Лин 13.10, Бопт 27.10, Уопт 10.11, ВиГ 24.11, Дин 08.12. Каждый связан со своим упражнением и SourceReference. Номера вариантов из ведомости не импортировались автоматически.

## Серверные инварианты

`taskVisibilityWhere` — общий фильтр публикации, группы и адресата. `requireTaskAudience` применяется к личным мутациям. `requireCoursePermission` ограничивает редакторские действия курсом текущей группы; manage_course не даёт verify_progress. Поиск, прямой URL и .ics следуют той же политике. Приватный реестр не загружается для студента и не передаётся редактору задач.

`verifyProgress` запрещает собственный зачёт, требует подтверждённую цитату или документ именно для пары task/user и сохраняет метод, автора и время. Прямой метод преподавателя требует отдельного teacher_confirm_progress:<courseId>, без автоматического права владельца. isTrustedAccepted применяется в аналитике и прогрессе. В существующей странице задания староста может выбрать другого адресата по никнейму и записать цитату/документ; форма не выдаёт такую запись за прямое действие преподавателя. Сохранение заметок отделено от смены статуса.

Перенос срока атомарно заменяет ACTIVE на SUPERSEDED, создаёт новый Deadline с originalDeadlineId и основанием, сохраняет локальное время и уведомляет адресатов. Конкурентный перенос старой записи отклоняется.

## Авторизация и интеграции

Dev-auth требует development и явного ALLOW_DEV_AUTH=true; пользователь выбирается только cookie, после проверки LOCAL_DEV identity. Production игнорирует эту cookie независимо от флага. Серверный Session reader хеширует токен SHA-256; OAuth и создание production-сессий ещё не реализованы.

Google Calendar API и outbox worker не реализованы: сервис возвращает NOT_IMPLEMENTED и никогда не записывает имитацию SYNCED. Экспорт .ics работает отдельно. AI-review меняет только статус предложения; кнопка больше не обещает применение изменений. Транскрипции читаются из БД, локальный корпус не является runtime-зависимостью. Импорта транскрипций в этом этапе нет.

## Проверки

`npm test` готовит отдельную studentvalue_test_core и запускает unit/integration тесты. `npm run test:e2e` поднимает собственный Next dev на 3301 с отдельной studentvalue_test_e2e и отдельным distDir и проверяет неизменность рабочих данных. `node scripts/check-migrations.mjs` разворачивает отдельную studentvalue_test_migrations и сравнивает фактическую схему с Prisma. `node scripts/check-production-auth.mjs` проверяет собранный production runtime на 3302 с ошибочно включённым ALLOW_DEV_AUTH.

Тестовые БД сохраняются для диагностики; их удаление автоматически не выполняется. PSQL_BIN и CREATEDB_BIN позволяют задать пути к PostgreSQL CLI. Google credentials не нужны для этапа.

Инструменты проверок: ESLint настроен без интерактивного мастера, Vitest обновлён до 5.x для устранения critical advisories старого runner. npm audit продолжает отмечать 14 moderate/high advisories в цепочках зависимостей; полная модернизация Next/Tailwind/Prisma не входит в этот этап и не считается выполненной.
