# Ежедневный интерфейс Student Value 1.984

Этап: 16 октября 2026. Надёжное учебное ядро остаётся основой данных и действий.

## Продуктовые решения

- Основной маршрут: Сегодня → Предметы → конкретная работа. Сроки — отдельный быстрый вход. На телефоне эти разделы всегда доступны в нижней навигации.
- «Сегодня» показывает один понятный следующий шаг, ближайшие даты, непрочитанные изменения, объявления и короткий личный прогресс. Рейтинг, достижения, настройки и управление группой находятся во вторичном меню.
- При выборе работы ближайшая сдача в течение недели приоритетнее далёкой текущей работы. Затем идут правки, текущая работа и будущие даты. Отправленная работа не предлагается для повторной отправки. Старые просроченные даты не захватывают главный блок навсегда, но остаются видны рядом и в списке сроков.
- Предмет — рабочая страница со списком работ, материалами, сведениями о преподавателях и личным прогрессом. Пустой список не выдаётся за доказательство, что на занятии ничего не задавали.
- Работа объединяет условия, личный этап, подтверждённый срок, заметки и раскрываемые первоисточники. Отметка студента и независимый зачёт визуально различаются. Запись результата старостой доступна отдельно от личного статуса.
- Фильтры сроков сохраняются в URL; доступны окончательные/рекомендуемые сроки, показ зачтённых и экспорт .ics. Календарь описывает разовый импорт без обещаний автоматической синхронизации.
- Поиск ведёт непосредственно к работе/предмету/материалу. Профиль содержит действующие настройки, без блоков «скоро» и неработающих интеграций.

## Визуальная система

Тёмный navy образует спокойный фон. Холодная светлая поверхность выделяет следующую работу и её содержание. Насыщенный синий используется для действий, burgundy/crimson — сдержанно в абстрактном знаке и прошедших сроках. Знак и жидкая лента — SVG, без внешнего сервиса, glow и буквальной полицейской символики. Основное содержимое организовано списками и разделителями, а не сеткой одинаковых карточек.

Длинные реальные названия переносятся; важные названия не обрезаются. Мобильный статус работы компактен; поля имеют размер шрифта 16 px, нижняя навигация учитывает safe area. Есть skip link, заметный keyboard focus, подписи полей, закрытие меню по Escape, сообщения ошибок сохранения заметок и уведомлений. Время пользовательских уведомлений явно задаётся в Europe/Moscow, чтобы сервер и браузер не расходились при hydration.

## Границы надёжного ядра

`src/server/queries/study-workspace.ts` создаёт только модель представления. Она использует существующие `taskVisibilityWhere`, `confirmedDeadlineWhere`, `progressEvidenceInclude`, `isTrustedAccepted` и расчёты московских дат. Персональные варианты по-прежнему разрешает `assignedVariants`. Новых академических записей, миграций, прав, учебных правил и интеграций нет.

Изменения сделаны в существующем приложении, без новых зависимостей. До работы созданы Git tag `checkpoint-before-daily-ux-20261016` и отдельный PostgreSQL dump с правами 0600. Скриншоты живой локальной БД получены только чтением. E2E работают на отдельной `studentvalue_test_e2e` и своём сервере 3301; рабочая БД сравнивается до/после.

## Проверка

- TypeScript, ESLint, установленный format check.
- 67 unit/integration тестов, включая 5 сценариев выбора следующей работы.
- 11 изолированных E2E сценариев. Помимо проверок прав, аудитории, вариантов, зачёта, заметок, источника нового задания и истории срока проверяются 9 страниц на ширинах 360/390/768/1440, переходы телефон → предмет → работа и Escape в меню. Рабочая БД не изменена.
- Production build. 56 запросов к production runtime с отсутствующими/поддельными сессиями и dev cookies при `ALLOW_DEV_AUTH=true` отвергнуты. В production отсутствуют формы локального входа.
- Свежая тестовая БД воспроизводится шестью сохранёнными миграциями; Prisma schema и PostgreSQL catalog совпадают.
- Отдельно осмотрены скриншоты реальных данных: Сегодня, каталог, САПР, предмет без опубликованных работ, задания с датой и без даты, сроки, поиск. 24 снимка страниц на 390/768/1440: HTTP 200, нет browser errors и горизонтального переполнения.

Проверки responsive выполнены в Chromium. Физический iPhone/Android и Safari отдельно не проверены.

## Что ещё нужно перед пилотом

Продакшен-вход не реализован; локальные аккаунты остаются только для разработки. Материалы, описания части работ, назначения вариантов и сведения о преподавателях заполнены неполно. Их нужно дополнять из реальных источников, не заменяя неизвестное демонстрационными данными. Остальные известные технические задачи предыдущего этапа, включая обновление зависимостей, не решались в этом UX-этапе. Полная панель старосты сохраняет прежние рабочие формы: здесь изменены её доступность из навигации и контекстные действия, а не весь административный workflow.
