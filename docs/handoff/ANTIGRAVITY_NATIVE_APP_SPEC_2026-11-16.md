## 2. Продукт и приоритеты

Приложение помогает студенту быстро увидеть ближайшие пары и аудитории, просмотреть сегодняшний/завтрашний день, найти работу и её материалы, разобраться с накопившимися лабораторными и увидеть личный прогресс. Оно не должно заставлять разбираться в административной структуре. Расписание не заменяет список незаконченных работ. Отсутствие подтверждённой даты сдачи не означает отсутствие задания.

Основной мобильный режим — «Поток»: открытая композиция без рамки вокруг главного события, дата над временем начала, читаемое название предмета, формат занятия, корпус/аудитория и преподаватель, ниже следующие события. Пользователь должен также быстро пробежать глазами весь день и переключиться на завтра. Desktop-сайт сохраняет рабочий обзор предметов/работ; его не нужно растягивать из телефонного макета.

Для текущей пары — визуальный прогресс. Владелец прямо просил не возвращать «Идёт сейчас», числовой обратный отсчёт и строки перерывов. ## 3. Выбранная архитектура

**React Native + Expo**, development/release builds с нативными компонентами. Next.js остаётся веб-клиентом и текущим backend. SQLite — долговременное хранилище мобильного клиента. Не менять стек на Flutter/Kotlin-only/Capacitor без выявленной конкретной блокирующей причины и отдельного обсуждения с владельцем. В первый день проверить актуальные совместимые стабильные версии Expo/RN и зафиксировать lockfile; не подбирать версии независимо и не использовать Expo Go как доказательство production-возможностей.

Возможная структура: `apps/mobile`, `packages/mobile-contracts`, позднее небольшой пакет чистой учебной логики. Не перемещай весь существующий Next-проект ради monorepo. Сначала изолируй конфигурации TypeScript, Metro, ESLint и тестов. Корневой web `tsconfig` сейчас захватывает `**/*.ts(x)` — RN-код не должен случайно проверяться как Next DOM-приложение. Исключи mobile source/build/keystores/device exports из Vercel/Docker web build inputs и проверь фактический архив/артефакт перед публикацией. Сохрани корневой lockfile/защищающие overrides; workspace и зависимости меняй осознанно, без npm audit fix --force.

Слои:

1. Native screens/navigation: отображают DTO и локальные состояния, не HTML.
2. Repository/use cases: выбирают локальные данные, обновляют их и управляют pending/error.
3. Local database: миграции SQLite, атомарная запись снимков/очереди, разделение public и user namespaces.
4. API client: таймауты, отмена запросов, ограниченный retry/backoff, строгая валидация, контроль размера, версия контракта.
5. Server adapters: `/api/v1/...`, проверка identity/scope, вызов существующих доменных операций.
6. Existing domain: PostgreSQL, provenance, права, выдача XP, verification и Calendar остаются серверными.

В мобильный bundle не импортируются Prisma, server actions, `next/*`, `.env` сервера, master credentials или серверные ключи. Поделить TypeScript-типы можно; React DOM-компоненты автоматически нативными не становятся. Общий backend не означает общие cookies.

## 5. Контракт публичного расписания

Сейчас существует `/api/timetable` с публичным РУЗ и проверками каталога; он не является готовым универсальным mobile API для личных задач. Не ломай его существующих потребителей. Введи explicit v1 projection/adapter со схемой, отдельной от сырого provider JSON. Не сериализуй Prisma rows целиком. Первый контракт может быть добавлен отдельно от endpoint — в таком случае не называй endpoint реализованным.

Минимум DTO: версия, полный group code и официальный RUZ ID, weekStart, состояние FRESH/STALE/UNAVAILABLE/UNCONFIGURED, fetchedAt/источник, дни и занятия с opaque occurrence ID, названием, исходными start/end, видом, преподавателями, аудиториями и примечанием подгруппы. Дата строго существующая YYYY-MM-DD, часы HH:mm, списки и строки ограничены. Состояние недоступности не маскируется пустой успешной неделей. Пустой день в успешно загруженной неделе отличается от дня вне загруженного диапазона. Изменения расписания могут менять occurrence identity: не использовать её как ID учебного задания.

## 6. Офлайн, синхронизация и достоверность

Нужно явно хранить время получения от источника и время сохранения на устройство; это разные величины. Состояния UI: обновление, актуальная копия, устаревшая копия, нет сети, ошибка конкретного источника, никогда не загружено, корректно пустой день. Перечёркнутый Wi-Fi показывается только при отсутствии соединения, не при ошибке РУЗ. Наличие сети не гарантирует успешный fetch. Кнопка повтора доступна, retry ограничен и не разряжает батарею бесконечным опросом.

Очередь изменений долговременна; после перезапуска восстанавливается. Каждая операция имеет UUID, user/device scope и base revision. На сервере idempotency key привязан к actor + operation; повтор с иным payload отвергается. Обработка операции и её результата/XP атомарна. Частичный timeout после commit не должен создавать дубль при retry. Ошибка одного элемента не стирает остальные операции.

Не синхронизировать операции одного аккаунта под другим. После logout не отправлять его отложенные изменения с новой сессией. Для первого среза при logout явно предупредить о pending операциях и удалить их вместе с приватным namespace; не терять их молча. При 401 нужен повторный вход, при 403 — сообщение об утрате права, при conflict — явное решение, а не переписывание чужих изменений.

Самостоятельное «выполнено» — не ACCEPTED. Учитываются существующие READY/SUBMITTED и независимая проверка. Владелец/староста не получает права принять собственную работу. Очки рассчитывает сервер, повтор/undo/recheck не умножает XP. Не выводить начисление на телефоне как подтверждённое до ответа сервера.

Расписание не доказывает, что занятие состоялось, задание выдано или срок установлен. Нельзя автоматически привязывать домашку ко всем лекциям и практикам предмета. Не выдумывать даты по названию архива, file mtime или порядку презентаций. Не «достраивать» вариант/допуск из учебного плана.

## 7. Вход и безопасность

Google OAuth только через системный браузер/поддерживаемый системный flow; не внутри управляемого WebView. Существующие scopes обычного входа не расширяются. Calendar — отдельное пользовательское согласие с текущим минимальным scope, не доступ к основному календарю/Drive.

Мобильный клиент — public client без embedded server secret. Проектируемый broker: приложение создаёт verifier/challenge; backend связывает mobile flow с PKCE challenge, проводит существующий Google flow с собственными проверками; после identity/enrollment transaction выдаёт короткоживущий одноразовый exchange code; приложение обменивает его с verifier на собственную отзываемую mobile session. Нужны binding к flow/device, проверка redirect allowlist, state/nonce, защита от replay, истечение, concurrency и negative tests. Не считать этот абзац готовой спецификацией endpoint без threat review. Если выбирается официальная native Google SDK схема, отдельно документировать доверенные client IDs/audiences и сохранить все проверки identity/enrollment.

Нельзя класть access/refresh credentials в query URLs, логи, AsyncStorage, обычную SQLite или source-controlled конфиг. OS secure storage для долговременных device credentials; access token преимущественно в памяти. Сервер хранит refresh credentials по безопасной модели, с rotation/reuse detection/revocation. Нужны logout текущего устройства и отзыв потерянной сессии. Обычный браузерный session cookie не копируется в приложение.

Персональные заметки/оценки/почта не становятся общегрупповыми данными. Шифрование приватных снимков проектируется вместе с хранением/удалением ключа, OS backup exclusions и logout. Нельзя обещать немедленное удаление уже скачанных данных с отключённого устройства или всех резервных копий. Сам platform owner не должен получать личные оценки и токены каждого студента.

Не собирать университетский master password «на всякий случай», не читать cookies браузера и не использовать аккаунт владельца для всех студентов. Публичные ключи/идентификаторы и серверные secrets различаются; список build-time публичной конфигурации должен быть явным.

## 8. Университетские сервисы и существующие ограничения

В реальном my.spbstu.ru проверены зачётка с таблицей/экспортом Excel, учебный план, поиск персоналий, университетские сообщения и ссылки на корпоративные сервисы. Отдельного делегированного API-доступа в просмотренных настройках не найдено; это не доказывает отсутствие API вообще. Исследовать официальные интерфейсы, а не угадывать endpoint по чужому старому репозиторию.

Сейчас `/university` содержит локальный импорт JSON-копий выбранных таблиц и явные внешние ссылки. Расширение-экспортёр подготовлено в `integrations/portal-bridge`, скачивание — `public/downloads/studentvalue-portal-bridge.zip`. Это ручная копия, не live connection. Оценки не были перенесены в общую БД. Не показывать «подключено» из наличия файла или ссылки.

Для каждого провайдера составить карточку: реальные доступные операции; способ согласия/отзыва; какие данные читаются; где хранятся; срок/состояние обновления; ограничения фоновой работы; поведение при отзыве; подтверждённый интеграционный тест. Только затем включать возможность пользователям. Читать Moodle через разрешённый web service — отдельный механизм от IMAP. OpenEdu не считать тем же Moodle. Мессенджер не считать почтой; сообщения не отправлять без явного пользовательского действия.

Подключение почты должно иметь отдельное ясное согласие, безопасное хранение credentials, ограничение скачивания и отдельные проверки чтения/отправки. Не загружать весь ящик/справочник в общую БД по умолчанию. Google Calendar остаётся опциональной независимой интеграцией; переезд хостинга его не отменяет.

## 9. Подпись, установка и обновления

Проверить сертификат именно распространяемого APK, applicationId, versionCode и путь установки. Текущее Gradle debug signing — не production-стратегия. Новый release keystore создать и сохранить приватно с независимой копией, не печатать ключи/пароли и не коммитить. Смена сертификата может потребовать удаления старого APK: объяснить это до действий, сохранить серверные аккаунты/прогресс, не обещать бесшовный upgrade. Не удалять приложение пользователя автоматически.

Dev/staging сборки отличаются ID и окружением. Не подключать их мутации к production, не оставлять кнопки смены пользователя и shared admin credentials в release. Указать проверенный способ локальной сборки и установки. Платный EAS, Google Play, Apple Developer, push credentials и новые аккаунты не покупать/создавать без нужного согласия. Android APK должен собираться без обязательного платного Expo cloud. OTA не является обходом подписания/совместимости и не заменяет выпуск новой binary при изменении native runtime.

## 10. Проверки и матрица приёмки

Для каждого пункта указывать PASS / FAIL / NOT RUN с артефактом. NOT RUN не засчитывается как PASS.

| Сценарий | Ожидаемый результат |
|---|---|
| Первый запуск без сети и без кэша | Объяснение отсутствия данных и доступный повтор, без бесконечного spinner и ложного «занятий нет» |
| Загрузка → force-stop → авиарежим → cold start | Загруженные пары читаются из SQLite без обращения к сайту |
| Перезагрузка телефона без сети | Сохранённые публичные данные доступны; приложение не требует скачать JS заново |
| Backend/DNS/РУЗ timeout/500/некорректный JSON | Старый корректный снимок не повреждён, причина и возраст видны |
| Восстановление связи | Ограниченная повторная попытка, атомарное обновление без дублей |
| Новый день/неделя/другой timezone | Московские даты, правильный ближайший день, нет вчерашней пары как будущей |
| Длинные названия/320–430 dp/крупный шрифт | Нет горизонтального overflow и потери основных действий |
| Свайп/кнопка/назад/повторное раскрытие | Одно понятное поведение, не три дублирующие навигации |
| Два пользователя/смена группы/logout | Данные и очередь не перетекают между аккаунтами; permissions на сервере |
| Повторная отправка одной операции | Один результат и одна корректная выдача XP |
| Ответ потерян после server commit | Повтор возвращает тот же результат, не новое действие |
| Архивирование/отзыв доступа/истёкшая сессия | Отказ в новых чтениях/мутациях, корректная обработка кэша/очереди |
| Google отмена/ошибочный state/replay/code expired | Нет выдачи сессии и автоматического членства |
| Материал | Проверенный ограниченный download, доступ только своей аудитории, offline чтение сохранённого файла |
| Напоминание/перенос/отмена | Нет дублей, старое напоминание не остаётся активным после успешной сверки |
| Release | Правильная подпись, отсутствие secrets/dev auth, установка и проверенный upgrade/reinstall путь |

Устройства: хотя бы реальный Android владельца либо согласованное тестовое устройство; эмулятор дополнительно; iOS simulator рано в процессе. Если физического устройства/SDK нет — честно отметить NOT RUN, подготовить воспроизводимый build и попросить конкретное необходимое действие, не сообщать об установленном приложении.

Backend tests — только отдельные локальные `studentvalue_test_*` БД и собственные порты/сборки. Тесты не должны обращаться к реальному РУЗ. Проверка реальных открытых данных отдельно от изолированных fixtures. Выполнить существующие проверки typecheck/lint/unit/integration/E2E/production-auth для затронутого ядра; миграции проверять на fresh и upgraded isolated DB. Никаких production fake identities.

## 11. Хостинг — параллельная, отдельно разрешаемая работа

Production пока Vercel Hobby + Neon Free. VPS не куплен; расходы не согласованы. `ops/` содержит подготовку Next standalone + PostgreSQL TLS + Caddy + backup/Calendar timers, но Docker startup/restore rehearsal на целевом сервере ещё не выполнены. Не называть это состоявшимся переездом. Не менять DNS, не удалять Neon/Vercel и не восстанавливать dump поверх populated DB. Нужны отдельный безопасный cutover, остановка записей, проверка полного восстановления, независимые off-server backups и rollback с учётом новых записей.

Разработка нативного клиента не требует немедленной покупки VPS. Не останавливай бесплатную независимую работу только из-за отсутствия платного хостинга. Не проводи новое широкое сравнение провайдеров вместо реализации приложения. Платежи, тарифы, новые security-sensitive permissions и необходимые интерактивные входы — реальные точки обращения к владельцу; обычные технические решения выбирай самостоятельно.
