# Проверка после e54650f — 17 ноября 2026

Независимая проверка текущего кода, GitHub release metadata, сохранённого скриншота устройства и точечных production HTTP-запросов. Испытание телефона, переустановка APK и развёртывание не выполнялись.

## Вердикт

Реальное нативное приложение развивается, но заявления «всё исправлено / A–C полностью сданы / готово для любого студента» не подтверждаются. Ранние претензии частично исправлены: есть обход всех чанков, SHA-256 от бинарных байтов, журнал operationId, навигация по дням и выбор расписаний. Эти результаты нужно сохранить. Количество тестов не доказывает полноту продукта или стабильность интерфейса.

## Критические факты

1. `scripts/mobile-test-server.ts` до этой проверки по умолчанию загружал рабочую .env, снимал SV_TEST_ISOLATED, включал dev auth, создавал test-user-rasool с VERIFIED enrollment и записывал сгенерированное SystemVerilog-пособие в offering-otu как официальное. Сервер слушает 0.0.0.0. Read-only запрос к локальной polytech_study подтвердил наличие этой личности и material-otu-lab1 с sourceNote «Официальное пособие». Не установлены все последствия прежних запусков; реальные записи не удалялись. Нужна отдельная provenance-проверка с резервной копией, точным перечнем артефактов, аудитом и обратимым исправлением. ОТУ и синтез нельзя смешивать по удобству теста.
2. Проверенные production URL `/api/v1/auth/mobile/start` и `/api/v1/tasks` возвращают 404. GitHub release v1.984 существует, содержит APK 173491818 байт и не помечен prerelease. Код debug-клиента по умолчанию выбирает http://10.210.5.173:3000. Поэтому наличие релиза не означает независимую от Mac работу. Проверка Custom Tab с локальным подтверждением не является Google login.
3. NewsModal содержит статические рассказы о публикации сессии, допусках по САПР/СОВД, открытии ПГАС и хакатоне, приписанные университетским подразделениям. Нет точных публикаций-источников; ссылки ведут в канал проекта. Это не подключённая новостная лента. CampusMapModal аналогично содержит вручную заданные координаты, этажи, лифты, входы и столовые без источников. Их достоверность не установлена — не выдавать за проверенный навигатор.
4. MaterialModal для бинарного файла показывает название/размер/описание сохранения. Нет действия, реально открывающего PDF/DOCX в просмотрщике. Загрузчик обходит чанки и хеширует байты, но для hash читает весь файл и создаёт base64/byte copies: это не потоковая проверка с постоянным расходом памяти. Нужен физический тест разрешённого PDF/ZIP >1 MiB, открытия, прерывания/возобновления и logout во время загрузки.
5. Mobile progress journal не атомарен с updateOwnProgress: отдельные операции чтения, изменения состояния и записи AuditLog, ошибки журнала проглатываются. Payload для повторного UUID не сверяется. progressSnapshot сохраняет studentNotes в общем AuditLog — нарушает правило не копировать приватные заметки в аудит. Ответ на старый UUID возвращает старый snapshot; outbox без version check записывает его в локальное состояние. Требуется атомарная идемпотентность с payload hash и безопасным reconciliation.
6. Новый путь прямого RUZ-запроса преподавателей/любых групп обходит более строгую серверную проверку: timeout снимается до чтения JSON, отсутствуют byte limit и проверка фактической запрошенной сущности/недели; отсутствующие days становятся семью пустыми FRESH днями. DTO-валидация уже построенного объекта не проверяет исходный ответ RUZ. Нельзя превращать ошибку схемы провайдера в «пар нет».
7. Wellbeing — локальный таймер и generic деление лабораторных на три части по названию. Это не рассчитанный по требованиям каждого предмета дневной минимум и не гарантия допуска. Счётчик фокуса не равен подтверждённому выполнению работ.

## Очерёдность продолжения

1. Сохранить PostgreSQL backup и отдельно исправить обнаруженные синтетические записи без массовой очистки/переноса локальной БД в production.
2. Исправить атомарность журнала, приватность заметок, session/logout boundaries и проверку RUZ; проверить конфликты, два аккаунта, отзыв доступа, медленный body и malformed response.
3. Подготовить проверенный production deployment мобильных API и настоящий Google вход существующего пользователя; проверить права обычного студента. Никаких локальных fake sessions в качестве приёмки.
4. Разделить debug LAN и production build profiles; production только HTTPS, отдельная постоянная подпись/keystore вне Git, нормальная версия и воспроизводимый APK. Не пересобирать или перезаливать прежний релиз молча; новый проверенный preview с честными ограничениями.
5. Довести PDF/DOCX offline opening и ежедневные сценарии, затем провести физические cold-start/offline/foreground/group-switch проверки. Скорость «16 ms / 120 FPS» подтверждать профилированием, причины вылетов — crash trace, не догадкой про Animated.loop.
6. Только затем полировать визуальную систему. Пять вариантов glow на одном layout — варианты палитры, не пять UX-концепций. Тёмно-синий сам по себе не проблема; приоритет — иерархия, читаемость, доступ ко всему дню и реальным работам. Cyberpunk противоречит исходным пожеланиям. Компактный список сегодня/завтра должен оставаться доступен из полноэкранного Flow без цепочки скрытых жестов.
